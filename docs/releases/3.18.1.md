**Bug fixes from a full code review: saved lists, bulk edits over open documents, the scanner, the shells and the offline cache.**

- **Types and tags.** Leaving the editor with unsaved changes asks first (the back button too). While the Tessel folder can't be read yet (right after the browser starts), the editor waits instead of showing this device's defaults; saving never writes those over the folder's own lists. Choosing a new Tessel folder keeps this device's lists when the folder can't be read at that moment. Moving the Tessel folder takes the lists along.
- **Tidy up and Analyse** wait for the lists in Settings before they start, and a document that is open in a reader with unsaved edits is written only once those are saved or dropped (they were reloaded over before). Tidy up's "couldn't read the text" errors name the real cause.
- **Rules:** a double tap on Add no longer adds a rule twice.
- **Search:** a renamed document is found under its new name at once; a document written while it was being indexed is indexed again rather than kept stale.
- **Reader:** an undo right after saving knows which version is on disk; a figure drawn after its block went away no longer leaks its pixels; a failed field, highlight or note edit no longer surfaces as an unhandled error; the engine maps a cancelled call to an abort and drops its listener.
- **Folders:** renaming a file so that only its case changes (Invoice → invoice) works on file systems that don't tell the two apart.
- **Scanner:** a camera whose detector failed no longer starts a new one on every render; importing photos while a picture is being taken waits; an export made ready just before a page was turned upright isn't rendered again during the save; the worker never hands out a cached page's own buffer.
- **AI:** a document id the model writes as part of a file name ("Rechnung 2024.pdf") no longer lands the answer on another document; an answer whose every category is off the list (the other language, say) is asked again; a model whose output limit is below 16 000 tokens (8192, 4096) is retried with the limit the server names instead of failing.
- **Android** rejects a file sent through Tessel's own documents provider; files handed over while the app was starting are taken too.
- **Mac app:** only the app's own origin gets its files and rights (not another host under the same scheme).
- **Offline:** the models cache is named by the models' contents, so a release that ships new models fetches them and an old cache goes; an error page from the host (a deploy half done) no longer replaces the kept page.
- **CI:** a failed tag lookup stops a release instead of releasing the version again; the signing secrets stay out of pull-request builds entirely.
